# 开馆风控台（Risk SOP）

[![CI](https://github.com/officekk88-ctrl/risk-sop/actions/workflows/ci.yml/badge.svg)](https://github.com/officekk88-ctrl/risk-sop/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
[![Node.js](https://img.shields.io/badge/Node.js-24.x-339933?logo=node.js&logoColor=white)](package.json)

面向匹克球馆筹建团队的开馆尽调、风险管理与 AI 辅助决策系统。它把项目建档、候选场地比较、37 项尽调清单、证据材料、风险整改、专家复核和版本化报告连接为可审计闭环。

> [!IMPORTANT]
> 本项目提供流程管理和辅助初审，不构成法律、消防、建筑结构、财税或其他持证专业意见。AI 结果不会自动进入正式风险或决策；需要人工审核确认，依法需要资质的事项应由合格专业人员处理。

## 完整功能框架

在原有 MVP 闭环基础上，系统已按产品框架扩展以下可操作模块：

- 智能项目建档问卷：建筑经营、权属租赁、消防工程、配套和邻里风险；
- 多候选场地：独立商业评分与合规风险评分、推荐排序、主场地和淘汰原因；
- 11 个标准开馆阶段与 8 个关键决策门，重大风险在服务端阻断直接通过；
- 普通项目任务与风险整改任务并行管理，站内提供到期和逾期提醒；
- 专家复核委托、资质有效期、接单/补充/交付/确认状态及专业意见归档；
- 材料批量上传、来源、提供人、证据形态、标签、有效期、敏感标记和版本号；
- 项目级角色（决策人、项目负责人、成员、审核人、外部顾问）；
- 企业统计分析、消息中心、系统参数配置和全量操作审计；
- 报告快照纳入阶段决策、决策门和已交付专家意见；
- PostgreSQL 完整模块结构见 `db/migrations/005_full_product_modules.sql`。

项目内的“全流程管理”是建档、选址比较、阶段、决策门、投资概况和普通任务的统一入口；依法需要资质的工作仍由线下专业人员完成，系统负责委托、记录和归档。文档明确列为暂缓或预留的电子签章、政府系统直连、专家交易结算、BIM/CAD、原生 App 和第三方通知通道没有伪造外部集成。

## 视觉设计

公开落地页和后台工作台采用统一的轻量 SaaS 视觉语言：白色留白、冰蓝柔光、深色标题、胶囊按钮、轻量卡片和顶部横向导航。设计方向参考 Aura 的 Therapy SaaS 模板，但产品品牌、中文文案、页面代码和业务组件均为本项目独立实现，没有复制模板源码或品牌素材。

- `/`：公开产品落地页；
- `/login`：登录入口；
- `/dashboard`：登录后的项目驾驶舱。

## 当前状态

一周 MVP 功能已进入发布候选版：核心业务闭环、AI 咨询/初审、人工确认、综合报告、账号权限和发布门禁已完成。领域专家评审、目标 Docker/HTTPS 环境验证和业务 UAT 仍需线下签收。

首页驾驶舱会列出当前账号可访问的全部未归档项目。顶部项目、完成率、重大风险和整改任务四张统计卡均可点击进入对应业务页面。每个项目独立显示尽调完成率、通过、不通过、待核实、待处理、开放风险和整改任务；点击“查看具体尽调清单”会直接进入该项目的尽调清单位置。所有适用清单均已判断且已生成最终报告后，项目自动归档，不再进入首页项目和统计数据。

## 快速开始

### 环境要求

- Node.js 24.x
- npm 11.x（随 Node.js 安装）
- 可选：Docker 与 Docker Compose

### 本地启动

```bash
cp .env.example .env.local
npm ci
npm run dev
```

启动前必须修改 `.env.local` 中的 `SESSION_SECRET` 和管理员密码；接入 AI 时再配置服务端 `OPENAI_API_KEY`。浏览器打开 `http://localhost:3000`。

### 系统边界与数据

项目、场地和固定尽调清单现已使用本地持久化适配器运行，数据保存在被 Git 忽略的 `.data/mvp-data.json`。该适配器只用于单机 MVP 验证；共享部署切换 PostgreSQL 后才能视为生产数据接入完成。

账号使用 scrypt 密码哈希，支持 ADMIN/MEMBER 角色、项目成员分配和项目级服务端权限校验。

管理员用户与权限管理现已接入：

- 仅 `ADMIN` 可进入“用户与权限”，查看和管理全部账号；
- 支持创建用户、修改姓名、调整 `ADMIN/MEMBER` 角色、启用/停用登录以及重置密码；
- 支持按用户勾选、取消和修改参与项目，项目负责人权限固定保留；
- 支持输入目标邮箱确认后删除账号，并同步移除其项目成员权限；
- 禁止删除或停用当前管理员、禁止移除自己的管理员角色、禁止移除最后一名启用管理员；
- 仍负责项目的用户不能直接删除，必须先转移项目负责人；
- 每次请求都会根据当前用户数据刷新角色和启用状态，停用、删除或降权会立即作用于已有会话。

当前已实现项目材料和风险整改闭环：

- 37 项尽调清单的每一项均提供独立材料上传入口，材料会自动关联到对应清单项；
- 清单项上传后立即执行 PDF/DOCX/OCR 解析和 AI 初判，综合该项全部已解析材料重新分析；
- 初判显示判断、置信度、分析、材料依据、建议和专家复核标记，所有结果均可人工修改；
- AI 初判与正式人工清单状态相互隔离，不会自动把检查项标记为“通过”；
- 材料支持 PDF、DOCX、JPG、JPEG、PNG，单文件最大 10MB；
- 服务端校验扩展名、MIME、文件头和项目访问权限；
- 删除采用软删除，文件立即不可访问，但物理副本暂时保留以便恢复和后续保留策略处理；
- 风险支持等级、证据、整改建议、关联清单和关联文件；
- 风险可生成整改任务，完成任务必须填写处理说明，关闭风险必须填写关闭依据。

AI 咨询与文档解析现已接入：

- 服务端通过 Responses API 流式输出，支持配置官方地址或 OpenAI 兼容网关；
- AI 自动带入项目概况、异常清单、正式风险和用户选择的已解析材料；
- PDF 与 DOCX 优先提取文本，扫描 PDF、JPG、JPEG、PNG 使用中英文 OCR；
- 会话和回答保存在本地 MVP 数据适配器中，项目权限在每次请求时重新校验；
- 首次 OCR 可能需要下载语言数据，扫描 PDF 单次最多识别前 10 页。

专业知识库与长期记忆现已接入：

- 按场地权属、规划用途、消防、工程、租赁法务、证照、体育运营、安全保险、投资财税、环保相邻关系等 11 个领域分类；
- 项目成员可提交经验、法规线索、专家意见或项目复盘作为“待审核学习”，不会直接影响 AI；
- 管理员可修订、审核发布、重新转为待审核或归档，每次保存都会递增版本并记录审核人；
- 只有已发布条目属于 AI 可用的受控长期记忆，系统按问题、项目和风险上下文检索相关条目；
- AI 使用知识时须标注 `KB-xxxx` 条目编号，知识与现场材料或主管部门意见冲突时仍须人工核验。
- 支持上传 PDF、DOCX、Markdown、XLSX 和 UTF-8 TXT（单文件最大 10MB），服务端先校验文件类型并提取文字，再由 AI 自动拆分、摘要和专业分类；
- AI 文档导入最多生成 8 条待审核候选，保留原始文件、解析方式、AI 摘要、模型、提示词版本、失败原因和候选条目关联；
- 与开馆尽调无关或证据不足的文档允许返回零条候选，禁止为满足格式要求虚构知识。

AI 文件初审与人工确认闭环现已接入：

- 从一份已解析材料生成摘要、关键字段、缺失项、候选风险、置信度和专业复核标记；
- 结构化结果使用 Responses API Structured Outputs，并由服务端 Zod Schema 再次校验；
- AI 候选风险与正式风险台账隔离，模型调用本身不会写入正式风险；
- 用户可以修改候选风险的标题、等级、描述、原文依据和建议后确认，也可以填写依据后驳回；
- 只有人工确认分支会创建来源为 `AI_REVIEW` 的正式风险，重复确认会被拒绝；
- 初审请求、结果、确认、驳回和正式风险写入均记录操作审计。

综合报告现已接入：

- 用户人工选择建议推进、附条件推进、暂缓推进或不建议推进，并填写决策依据；
- 每次生成独立版本快照，源数据后续变化不会无痕修改旧报告；
- 在线报告包含审核范围、项目、材料、清单、风险、整改、决策、前置条件和适用声明；
- 服务端生成带中文字体、分页、页码和“内部初审”水印的 PDF；
- 待确认 AI 候选风险不会进入报告。

服务端 AI 环境变量示例：

```bash
OPENAI_API_KEY=replace-with-a-rotated-secret
OPENAI_BASE_URL=https://example-compatible-gateway.test/v1
OPENAI_MODEL=gpt-5.6-sol
OCR_LANGUAGES=chi_sim+eng
```

当前机器如果只有 Windows Node 而 WSL 中没有 Linux Node，可使用 Windows Node 调用 npm：

```bash
'/mnt/c/Program Files/nodejs/node.exe' \
  'C:\Program Files\nodejs\node_modules\npm\bin\npm-cli.js' run dev
```

## 质量检查

```bash
npm run typecheck
npm run lint
npm run build
npm run test:unit
npm run test:account
npm run test:security
npm run test:recovery
npm run test:checklist-ai
npm run test:checklist-upload
npm run test:user-admin
npm audit --omit=dev --audit-level=high
```

`test:account` 验证真实管理员登录、成员分配、成员登录和项目权限；`test:security` 验证权限、安全响应头、跨站请求、报告下载和本机 P95。运行前需先执行 `npm run build`，完整发布门禁可执行 `npm run test:release`。

## 数据库

PostgreSQL 迁移位于 `db/migrations/`。`001_init.sql` 覆盖一周 MVP 基础实体，`002_checklist_evidence_ai_assessments.sql` 增加材料与清单项关联、逐项 AI 初判及人工修改记录，`003_user_administration.sql` 增加账号启停及角色索引，`004_knowledge_base.sql` 增加可审核、可版本化的专业知识库，`005_knowledge_document_imports.sql` 增加知识源文档及 AI 导入追踪。

## 模拟演示项目

可重复执行以下命令，创建“37项全部通过”和“土地/证载用途不合规”两个模拟项目：

```bash
npm run data:seed:simulations
```

命令只会替换这两个固定 ID 的模拟项目，不删除其他项目，也会保留两个模拟项目已有的 AI 会话和材料初审记录。它会生成21份带显著“模拟材料”标识且已关联具体尽调项的 PDF、74个清单实例、3条风险、3项整改任务和2份决策报告；全项通过项目默认为已归档，土地性质不合规项目继续显示为待处理。所有内容均为虚构，不具法律效力。

## 容器启动

已安装 Docker 时，将 `.env.example` 复制为 `.env` 并替换密钥后可运行：

```bash
docker compose up --build
```

健康检查地址为 `GET /api/health`，`app-data` Volume 持久化业务数据。容器启动前会强制检查密钥、管理员密码和应用域名。Compose 中的 PostgreSQL 服务仅作为迁移目标参考 profile，当前 MVP 运行时未使用它。详见 [部署与回滚说明](项目文档/部署与回滚说明.md)。

如果受控测试环境明确只提供 HTTP，可设置 `ALLOW_INSECURE_HTTP=true`，并通过 `WEB_PORT` 指定宿主机端口。该模式会关闭会话 Cookie 的 Secure 标记，流量不受 TLS 保护，不应作为正式公网生产配置。

## 安全说明

- 不要将 `.env.local` 提交到代码仓库；
- `OPENAI_API_KEY` 只能由服务端读取，禁止使用 `NEXT_PUBLIC_` 前缀；
- 默认演示凭据仅供本地开发，共享环境必须替换；
- AI 输出只能作为辅助初审，正式风险必须经过人工确认。

漏洞请不要提交公开 Issue；请按 [安全政策](SECURITY.md) 中的私下报告方式处理。
