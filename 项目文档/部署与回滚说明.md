# 部署与回滚说明

## 1. 适用范围

当前版本是单实例 MVP，业务数据和上传文件保存在 `/app/.data`。适合受控内网试点，不支持多实例水平扩容。PostgreSQL 迁移脚本已建立，但运行时适配尚未切换。

## 2. 上线前准备

1. 安装 Docker Engine 和 Compose v2，确保主机可持久保存 Docker Volume。
2. 从 `.env.example` 创建仅保存在服务器的 `.env`。
3. 设置长度至少 32 位的 `SESSION_SECRET`、长度至少 12 位的管理员密码、HTTPS `APP_ORIGIN` 和服务端 AI 密钥。
4. 将域名反向代理到 `127.0.0.1:3000`，在代理层启用 TLS。

```bash
npm ci
NODE_ENV=production npm run env:check
npm run test:release
docker compose up -d --build
docker compose ps
curl -fsS https://your-domain.example/api/health
```

容器在环境变量不安全时会拒绝启动。AI 密钥缺失只会警告，其他业务功能仍可用。

## 3. 备份与恢复

非容器单机部署可在停止写入后执行：

```bash
npm run data:backup -- /secure/backups
```

恢复前必须停止应用，先备份现有数据，再执行：

```bash
npm run data:restore -- /secure/backups/mvp-<timestamp> --confirm
npm run test:recovery
```

Compose 使用命名数据卷，应通过容器复制，不要把工作区中的 `.data` 当作容器数据：

```bash
mkdir -p backups/pre-release
docker compose stop web
docker compose cp web:/app/.data backups/pre-release/.data
docker compose start web
```

容器恢复时先停止 `web`，将当前数据再备份一次，然后执行 `docker compose cp backups/pre-release/.data/. web:/app/.data`并重启。恢复后必须重跑健康检查和核心链路冒烟。

## 4. 版本回滚

1. 标记失败版本并保留现场日志：`docker compose logs web`。
2. 停止服务：`docker compose down`，不要使用 `-v`。
3. 切换到上一个已验收代码标签，重建镜像。
4. 如数据结构也发生变化，按上节恢复发布前备份。
5. 验证健康接口、登录、项目访问、文件下载和 PDF 报告。

## 5. 运维检查

- 每日检查健康接口和容器重启次数；
- 每日增量、每周全量备份，异机保存并每月恢复演练；
- 不在日志、工单或截图中记录 AI 密钥和密码；
- 单实例试点超出后，先完成 PostgreSQL/对象存储适配再扩容。
